# SwiftCargo 貨運異常處理與流程改善

**商業流程分析 · 流程改善 · SAP Signavio · BPMN 2.0**

這個作品集呈現我如何把複雜的物流案例轉換為可討論、可檢查的商業流程：釐清各角色責任、辨識跨部門交接、描述逾時與取消等例外，並從流程中提出可衡量的改善方案。

原始成果是使用 **SAP Signavio 製作的 AS-IS BPMN 模型**。本作品集另外加入改善分析與 KPI 計畫；新增方案屬於後續設計提案，尚未在企業環境導入或量測效益。

## 案例與模型

SwiftCargo 是昆士蘭大學 BISM7216 課程中的虛構物流企業。案例涵蓋貨運延誤、損壞、遺失與誤送等異常，由客戶體驗主管、理賠人員、優先救援團隊、品質與合規人員共同處理。

原始模型包含 **4 個參與者 pools、9 個圖面、64 個 tasks、8 個一般子流程及 1 個 ad-hoc 子流程**，另有 155 條順序流與 24 條訊息流。這些數字是檔案盤點結果，不代表評分或流程已通過完整驗證。

檢視發現一條回饋提醒訊息流缺少起點與終點、部分計時器缺少正式設定，部分圖面標籤也需要整理。這些情況列在模型檢視文件中；原始模型保持不變，方便讀者直接核對。

## 流程改善思路

1. **改善前端資料品質：** 使用結構化表單與明確案件負責人，減少資料不足造成的等待。
2. **強化時限管理：** 明確定義到期時間、提醒與升級接收責任，避免交接後失去追蹤。
3. **減少重複紀錄：** 以案件事件作為一致的更新來源，同步系統、日誌與管理檢視。
4. **拆開結案與回饋追蹤：** 將已完成的營運處理與尚未收到的客戶回饋分開管理，並保留再開案途徑。
5. **建立改善追蹤閉環：** 為每個改善事項指定負責人與期限，於月度檢討確認結果。

每項提案在 [改善分析](docs/improvement-case.md) 中列出依據、取捨與驗收條件，在 [衡量計畫](docs/measurement-plan.md) 中定義指標。未提供實際案件紀錄，因此不宣稱已節省成本、縮短處理時間或提升滿意度。
